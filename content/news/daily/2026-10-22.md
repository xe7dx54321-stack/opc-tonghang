今天的主线是 AI 从模型能力走向可交付的系统：Anthropic 把代理推向跨应用工作流，OpenAI 模型进入 Google Cloud，NVIDIA 则把新一代机架变成云实例。另一端，芯片厂建设、人形机器人进厂和无人车机场接驳，都给出了比演示更可核对的进度。几项动作处于研究预览、私有预览或明年试点阶段，阅读时要把宣布与实际开放分开。

## Anthropic 推出 Claude Duet 研究预览，向专业用户开放跨应用代理

Anthropic 的 [Claude Duet](https://www.theverge.com/ai-artificial-intelligence/1015843/anthropic-claude-duet-ai-agent) 让 Claude 从聊天窗口走向持续运行的工作代理。它面向专业人士和小企业，能查看用户连接的应用，早上整理简报，白天提醒需要处理的变化，也能接下安排会议、做仪表板或构建网页应用等任务。Duet 使用 Claude Opus 5.5，调用现有记忆、技能和连接应用，并借助带浏览器的虚拟机操作。入口包括 Claude 网页版及 iOS、Android 独立应用。

真正要看的是它如何处理权限。报道引述 Anthropic 说，**支付、删除等重要步骤会先征求批准**；公司也为敏感信息设置额外的拦截机制。这些设计降低了代理直接执行高风险操作的门槛问题，但不能消除误读上下文或错判优先级的风险。Anthropic 自己将产品称为研究预览，并承认它仍可能误读讨论串。

对企业软件市场，这意味着代理竞争开始从单次回答转向“能否长期接住工作”。接入的应用越多，权限设计、可追溯记录和失败后恢复越重要。Duet 的胜负暂时不在功能清单，而在能否让用户放心交出跨工具任务，以及处理出错时能否把控制权交还给人。

## OpenAI 模型进入 Google Cloud，企业先获私有预览

据 [Ars Technica 报道](https://arstechnica.com/ai/2026/10/openais-latest-ai-models-are-coming-to-google-cloud-and-antigravity/)，OpenAI 与 Google Cloud 的合作将把 GPT 模型带进 Model Garden，也会让 Google 的 Antigravity 编程工具接入 OpenAI 模型。OpenAI 的[官方公告](https://openai.com/index/openai-models-google-cloud/)确认了模型及 Codex 工作流进入 Google Cloud 的安排。Google Cloud 原本已有 Gemini 和 Claude，企业如今可以在同一云平台比较三家闭源模型的适用任务。

开放范围需要仔细读：**三款 OpenAI 模型目前先向选定企业客户提供私有预览**，更广泛的可用时间还没有等同于“今天已经上架”。报道说推理运行在 Google 的基础设施上，交易可通过 Google Cloud Marketplace 处理；已有云采购承诺的企业，测试模型的采购路径会变短。但实际价格、区域、数据治理条款和性能仍须在账户可用后逐项核对。

更大的变化在分发权。模型公司通过更多云入口接近企业客户，云平台也由推自家模型变成同时销售多家模型。对采购方，这提高了替换模型的谈判空间；对模型公司，能否进入既有企业采购和开发工具，正在与模型本身的评测分数一起决定收入机会。

## AI 辅助发现 PHP 严重漏洞，OpenAI 与 Wiz 披露协同修复

[OpenAI 的披露文章](https://openai.com/index/coordinated-disclosure-of-critical-vulnerabilities/)说，其合作研究人员借助 GPT-5.6 Sol 在 PHP 中找到严重漏洞，Wiz 也独立发现并报告了相关问题；PHP 维护者主导修复和发布，安全厂商协助提前准备防护。[The Decoder 的报道](https://the-decoder.com/openais-gpt-5-6-sol-and-gemini-4-argon-discovered-the-critical-php-vulnerability-affecting-millions-of-websites/)记录了这次公开披露以及供运营者检查 PHP 版本的工具。发现和协调跨越此前数月，今天的新闻是**公开披露与补丁响应**，不是模型今天才发现漏洞。

这件事对网站运营者的含义很直接：检查所用 PHP 版本，并按 PHP 官方和服务提供商的指引升级。漏洞波及范围、可利用条件不能只从“影响数百万网站”的标题推导；实例是否暴露取决于版本与部署方式。把注意力放在补丁和资产清单上，比在模型之间排“谁先发现”更有用。

对 AI 安全产业，可信的信号是模型已经进入真实的漏洞研究和协调披露流程。它能帮助防守方扩大排查能力，同样可能让攻击方更快改造利用链。今天的投入重点因此是缩短从发现、验证到补丁落地的时间，而不是把一次发现写成自动化安全已经成熟。

## Recursive 发布可在笔记本运行的 Flint 编程模型

Recursive 发布首款模型 [Flint](https://techcrunch.com/2026/10/21/recursive-launches-flint-a-laptop-coding-model-it-says-was-largely-built-by-ai/)。TechCrunch 介绍，它是一款可在笔记本本地运行的编程模型，权重可下载，使用 Apache 2.0 许可。模型采用 MoE 架构，报道给出的规模是 400 亿总参数、每次任务激活 25 亿参数。对担心代码外传或按 token 支付成本的开发团队，本地运行提供了另一种部署方式。

更引人注意的是 Recursive 对研发过程的说法：其 Eureka Machine 自动化研究系统参与了 Flint 的多个环节，团队据称在不到四个月内完成模型开发。但这仍是人在监督下使用 AI 研究助手，**不能把一次模型发布直接等同于自主递归改进**。公司的速度和性能数字来自自测，公开权重给社区复核提供了起点。

实际分水岭会是仓库级任务，而不是生成速度。一个本地模型若能在普通设备上稳定理解代码、修改文件并通过测试，才会真正影响编程代理的部署成本。Flint 给出了可检验的技术和许可条件，接下来应看独立开发者在真实项目里的修复成功率与内存占用。

## Google Cloud 与 NVIDIA 公布 Vera Rubin A5X 云实例，下月计划正式开放

[NVIDIA 公告](https://blogs.nvidia.com/blog/google-cloud-vera-rubin-infrastructure/)把 Vera Rubin NVL72、ConnectX-9 网络、Google Cloud Virgo 网络与液冷整合进 A5X 云实例。它瞄准训练、推理和大规模强化学习等负载，已有早期客户接入。**实例的普遍可用安排在下月**，欧洲扩展也只是计划；把公告标题理解成所有客户今天已经能买到，会高估当前供给。

Google Cloud 提出的多站点规模目标是最多 96 万颗 Rubin GPU。这个数字说明它设想的集群尺度，却不是已交付装机量。现阶段更硬的信号是云厂开始按完整系统采购与部署：GPU、CPU、网络、供电、散热以及运维软件要同时就位，单个芯片规格好看还不够。

对半导体及算力基础设施投资，A5X 提醒一个判断：竞争从芯片参数转到整机架交付和实际利用率。后续应该盯实例如期开放、早期客户是否扩大负载，以及液冷和网络链条能否跟上，而不是先把规划中的 GPU 数量计入现实产能。

## Intel 亚利桑那 Fab 62 开始安装生产设备，量产节点尚未公布

据 [Tom’s Hardware 报道](https://www.tomshardware.com/tech-industry/semiconductors/intel-installs-production-tools-at-fab-62-in-arizona-provides-updates-on-ohio-chip-fab-confirms-high-na-euv-for-high-volume-manufacturing-in-2028)，Intel 已在亚利桑那州 Fab 62 开始安装生产设备，目标在 2028 年底前使工厂进入量产。厂房建成后，设备入厂是产线建设中能看到的具体进展；它比单纯重申美国制造计划更接近实际资本开支。

但要把进度读细：Intel **尚未正式指定 Fab 62 的制程节点**，也没有给出精确的高产启动日期。报道提到 Intel 14A 是外界讨论过的可能用途，不能写成已经确定的生产安排。工具安装、工艺调试、良率爬坡和客户认证之间仍隔着多道关，今天只能确认第一道设备建设动作。

对设备、材料和先进制程链条，后续更有意义的是实际采购与验收、节点分配和客户订单。若这些信息逐步落地，Fab 62 才能从长期产能计划变成可以估算的供应。现在把 2028 年目标直接折成出货量，依据还不够。

## AGCO 与 Agility 签约引入 Digit，人形机器人试点拟于 2027 年启动

[The Robot Report 报道](https://www.therobotreport.com/agco-to-deploy-agility-digit-humanoid-in-kansas-factory/)，农业设备制造商 AGCO 与 Agility Robotics 签署商业协议，准备在堪萨斯州 Hesston 的工厂使用 Digit 人形机器人。美国试点**预计到 2027 年才开始**。它是客户和供应商之间的正式合作，距离可持续的工厂部署仍有一段路。

这条值得看，是因为农业装备制造的工位和物流流程比舞台演示复杂得多。AGCO 提到希望让机器人承担重复、费力或有危险的任务，但报道没有披露机器人数量、具体岗位、单班运行时间或投资回收期。现阶段可以确认的是试点对象与地点，不能由签约推出规模收入。

对具身智能公司的商业化评估，客户愿意把机器人带进真实工厂只是第一步。下一步要看到工序适配、车间安全、故障恢复与人工协作的数据。谁能在这些指标上拿出连续运行记录，谁的订单才更容易从试点转向复制。

## Waymo 开通拉斯维加斯机场接驳，初期仅向少量乘客开放

Waymo 已开始提供往返拉斯维加斯 [Harry Reid 国际机场的无人车服务](https://techcrunch.com/2026/10/21/waymo-starts-offering-rides-at-the-las-vegas-airport/)，乘客在一号和三号航站楼的指定区域上下车。报道说这是 Waymo 服务的第六座主要机场，但**初期只向少量乘客开放**，并非全体用户一夜之间都能叫到车。

机场是自动驾驶运营能力的一块硬试金石：道路可以提前规划，乘客却会集中在航班到达后涌入，接驳点还受机场管理规则约束。开通说明 Waymo 与机场的服务接口向前走了一步；它本身不证明高峰期吞吐、排队体验或单车经济性已经达标。

对机器人出租车商业化，城市覆盖面积常被拿来展示扩张速度，而机场接驳更适合观察高价值、高密度场景能否稳定运营。真正有分量的后续数据，是乘客覆盖范围扩大后等待时间和完成订单的变化。

## 小红书公布 DoSA 长上下文加速方法，称首 token 延迟降低 37% 至 48%

[小红书技术团队的文章](https://mp.weixin.qq.com/s?__biz=Mzg4OTc2MzczNg==&mid=2247496757&idx=1&sn=42a95f2ad3ebc18eac32f7de5aae14e3)把长上下文推理的瓶颈指向稀疏注意力索引器：主注意力虽然少算了，负责找出 Top-K token 的筛选过程仍可能吃掉大量预填充时间。DoSA 用分数的上下界，先证明一部分候选不可能进入 Top-K，再对保留项完整计算。

团队称这保持了**原始评分函数下的精确 Top-K**；在约 100 万 token 的测试中，三款模型相对各自 SGLang 基线的首 token 延迟下降约 37% 至 48%。这里的“无损”是数学筛选结果的限定说法，不能直接扩写为任何模型、任何硬件上都无质量损失。数据也来自厂商自测，独立复现尚是下一道门槛。

这条的产业意义在于推理优化不一定要换模型或牺牲精度，索引器和 GPU 内核仍有系统空间。对服务长文档、代码库和复杂 Agent 上下文的平台，应该比较完整预填充链路的延迟、显存和吞吐，而不是只看注意力计算量。

## Flapping Airplanes 宣布完成 10 亿美元 A 轮，估值报道约 60 亿美元

据 [TechCrunch 报道](https://techcrunch.com/2026/10/21/year-old-ai-lab-flapping-airplanes-raises-1b-at-a-6b-valuation/)，成立约一年的 Flapping Airplanes 宣布完成 **10 亿美元 A 轮融资**，Index 与 Lux 共同领投。报道将约 60 亿美元估值标为消息来源说法，不宜当作公司正式确认的定价。相较九个月前的种子轮，这笔钱显示资本市场继续押注训练效率路线。

团队提出的方向是让 GPU 在训练、推理等不同负载之间少空转，同时用更少数据训练模型。报道介绍其所谓 megakernel 框架，但这仍主要是团队给出的技术主张；公开可复核的模型效果、长期稳定性和成本数据不足以从融资额中反推出技术领先。

对投资判断，融资规模说明“如何更高效使用算力与数据”已能吸引与模型本体同等级别的资本。它也抬高了验证要求：资金如何转化成公开产品、单位训练成本如何下降、客户愿不愿付费，比估值上升更能说明这条路线是否成立。
