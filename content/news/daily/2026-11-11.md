## Anthropic启动IPO路演，拟定每股70至78美元

[Anthropic 官方公告](https://www.anthropic.com/news/roadshow-launch)称，11月10日已启动拟议首次公开募股的路演。此次拟发行 **8.25亿股** A 类普通股，其中约8.01亿股由公司发行，其余为现有股东出售；预期发行价为每股 **70至78美元**，公司申请以“ANT”为代码在纳斯达克上市。这些数字描述的是发行方案，不是已完成的募资额，更不能把区间上限写成最终成交价格。

这条与10月公开提交招股书是同一条上市故事的下一步，今天的新动作是把文件中的上市意向推进为面向投资者的路演和定价区间。模型公司在上市前争取更高估值，投资者则有机会用公开材料逐项核对收入、亏损与长期算力承诺。就目前的公告而言，最重要的仍是条件性：承销安排、最终定价和上市结果都尚待确定。把拟议发行与已经收到的现金混为一谈，会让模型公司的资金缓冲看起来比实际更厚。

这场路演也给同行提供了一个定价参照，但不能简单用发行股数乘价格推断任何竞争对手的价值。资本市场要判断的是增长能否覆盖训练、推理和分销的持续投入；随着产品线扩展到办公与 Agent，商业化速度和毛利质量需要一起看。

## Anthropic扩展Claude办公套件，表格与白板进入测试

据 [TechCrunch 报道](https://techcrunch.com/2026/11/10/anthropic-launches-claude-meetings-to-turn-workplace-discussions-into-plans-and-tasks/)，Anthropic 11月10日公布了 Claude Sheets、Whiteboards、Data 和 Meetings 等工作场景功能。白板与表格已在付费方案中进入测试；[Anthropic 官方说明](https://claude.com/resources/articles/more-ways-to-work-with-claude-sheets-whiteboards-and-interactive-connectors)同时强调互动连接器，可以让合作伙伴把应用嵌入 Claude。官方将 **Claude Meetings 表述为“即将推出”**，所以不能把它与已进入测试的白板、表格写成同样的开放状态。

这次值得看的不是“又多了几种文档”，而是上下文在工作流程中如何移动。企业数据分散在邮件、表格、会议和业务系统里；如果 Agent 只能给出建议，员工仍要把结果复制到下一套工具。互动连接器和可编辑的产物把 Claude 往执行界面推了一步，竞争对象因此也从聊天窗口扩到协作软件的日常入口。

能否替代现有办公环节，还要看权限和操作记录。会议中做出的改动如何让参与者核对，表格单元格的计算来源能否追溯，跨应用的连接由谁授权，这些问题比演示视频更接近企业采购。今天确认的是产品范围与测试状态，持续使用率和节省工时仍需要客户侧数据。

## OpenAI推出ChatGPT商家资料与品牌Agent测试版

[OpenAI 公告](https://openai.com/index/introducing-businesses-chatgpt)推出 Businesses in ChatGPT 测试版。商家可在 Business Hub 认领资料，维护企业信息，并提交带价格和可售状态的产品信息；Business Agents 则先面向美国符合条件的电商和在线服务商开放。它让商家从“被模型提及的对象”变成能够直接维护资料、与用户交互的一方，但目前开放范围有明确地区与类别限制。

这改变了 AI 搜索入口的经济关系。传统搜索依赖网页索引、广告购买和跳转，新的商家资料入口使平台有机会拿到更及时的商品数据，并在用户比较选项时接上品牌对话。商家得到一个新的获客渠道，平台则获得更结构化、可更新的供给信息。两边都要接受新的约束：资料由商家维护，可信度、排序与商业推广的边界需要让用户看得清楚。

OpenAI 说明赞助展示会明确标注，并与普通回答分开。这个设计原则值得记下，但今天没有足够证据判断它能给商家带来多少订单，也不能从测试版推断所有商家都已可创建 Agent。对应用层团队，实际值得跟踪的是资料维护成本、用户从回答走向商家服务的转化，以及平台是否提供可验证的效果数据。

## 台积电批准分别最多5亿美元投资Anthropic与OpenAI

[台积电董事会决议](https://pr.tsmc.com/english/news/3352)批准两项股权投资上限：在 Anthropic 的 IPO 中，以发行价认购不超过 **5亿美元**普通股；另以不超过 **5亿美元**认购 OpenAI 优先股。这里的关键词是“批准”和“不超过”，而不是已完成交割。同份公告还批准约 **409.27亿美元**资本支出安排，涵盖先进制程、先进封装、厂房及研发等用途。股权投资与资本支出是不同项目，不应相加当成某一客户的订单。

这项决议值得关注，因为一家关键晶圆代工厂同时把两家模型公司纳入资本配置。模型开发商需要持续取得先进芯片，台积电则要面对巨额产能建设和客户需求波动；在这种关系里，股权可以增加彼此的长期利益关联。不过公告没有给出排他供货、优先产能或特定芯片订单，不能由投资上限倒推出供应协议。

对半导体投资，真正的验证点仍在产能利用率和先进封装交付。董事会授权说明管理层愿意配置资本，尚未说明何时认购、持有多久、相关客户实际采购多少晶圆。若把股权新闻当作晶圆订单，容易高估可见收入；若完全忽略它，也会漏掉芯片供应链与模型公司之间正在变密的资本联系。

## 蚂蚁灵波开源LingBot-Touch，尝试让触觉跨灵巧手复用

[量子位](https://www.qbitai.com/2026/11/508996.html)与[智东西](https://mp.weixin.qq.com/s?__biz=MzA4MTQ4NjQzMw==&mid=2652813612&idx=1&sn=f9954acd08acd5447e99dccda7f81f08)都报道了蚂蚁灵波11月10日开源 LingBot-Touch。两篇指向同一次发布，不是两条独立事件。量子位称模型基于近 **5000小时真实触觉数据**，把磁触觉、视触觉和压阻式等传感信号转成共享表征，供不同灵巧手与动作模型使用。报道援引发布方的真机测试：两款手、四种动作模型、26项任务，平均成功率较无触觉时提升约14至26个百分点。

机器人抓取的难点常发生在手指碰到物体之后。视觉能帮助定位，却不一定能判断瓶盖是否打滑、材料是否将被捏坏；触觉加入闭环后，动作模型才有更多反馈可供修正。这次技术路线的关键是**跨传感器复用**：如果不同硬件输出能接入同一表示层，团队换手或换传感器时便不必从零重做全部训练。

但目前展示的是发布方挑选的任务和硬件组合，不能据此推断所有灵巧手都能直接迁移。下一步需要第三方在未参与训练的设备、不同物体与更长任务链上复测，尤其要看失败后的恢复能力。这个指标比单次拧瓶盖成功率更能决定触觉基础模型是否成为可复用的机器人底座。

## 微软研究揭示模型权重后门，可诱导Agent执行恶意命令

[Microsoft Research](https://www.microsoft.com/en-us/research/blog/lazare-veni-foras-reprogramming-dormant-neurons-to-backdoor-ai-agents/)披露名为 Lazarus 的模型权重后门技术。研究团队称，攻击者可以改写休眠神经元，让平时看似正常的 Agent 在隐藏触发条件出现时执行恶意命令；植入过程**不必重新训练整套模型**，常规测试也未必能发现。风险在有工具调用或终端权限的 Agent 身上尤其具体，因为模型输出可以进一步触发下载代码、读取秘密或运行命令。

这是一次研究展示，并非已经证明存在大规模真实入侵。它提醒企业，Agent 的安全边界不只在提示词、工具权限和应用代码，还在导入的模型权重本身。若模型从第三方仓库下载，再由内部系统赋予调用权限，权重来源和完整性就成为部署链路的一环；只在上线前问模型几道安全题，很难覆盖这种带触发条件的行为。

微软同时介绍了模型来源核验、权重扫描、签名与审计等防御方向。采购团队最实际的动作，是把“从哪里拿到权重、谁能修改、何时签名验证”写进与软件依赖同等级的审查流程。防御效果仍需在不同模型、攻击方式和真实工具环境中检验，不能因为供应商列出工具就认定风险已经消失。

## Gemini 4 Carbon扩大开放，从防御试点走向付费API

[Google DeepMind 公告](https://deepmind.google/blog/gemini-4-carbon-is-now-available/)表示，Gemini 4 Carbon 现向开发者、企业、科研人员和消费者扩大开放。两周前它只提供给 Fairwind 项目的部分网络安全防御者，因此今天的新闻是**开放范围变化**，并非 Carbon 首次发布。Google 称付费开发者与企业可通过 Google AI Studio API 等入口使用，Google AI Ultra 订阅用户会在相关产品中逐步获得访问。

官方把 Carbon 放在复杂、多步骤编码、调试和开放式研究等高强度任务上，而把 Argon 描述为多数日常软件工程与知识工作的选择。它还预览了 Antigravity 的 `/swarm` 多 Agent 协作功能。这里的产品逻辑是分层：昂贵、深度的推理不必承担所有步骤；多 Agent 并行也不自动意味着更便宜，协调、验证和重试可能增加总 token 消耗。

Google 公布的付费 API 入门价格与 Argon 相同，为每百万输入 token 2美元、输出 token 10美元，但实际任务成本还取决于执行步数和成功率。开发者真正要比较的是“完成一个复杂任务花多少钱、需要多少人工核对”，而非只看榜单名次。此前防御试点的成绩来自 Google 自述，扩大开放后才有更广泛复测的机会。

## DeepMind发布Gemini Robotics 2.5，公布工厂概念验证

[DeepMind 官方发布](https://deepmind.google/blog/gemini-robotics-2-5-accelerates-real-world-physical-intelligence/) Gemini Robotics 2.5 视觉语言动作模型，并称正在向机器人合作伙伴开放。团队称测试覆盖 **超过200种任务**；在奔驰产线的概念验证中，Apptronik Apollo 2 完成汽车零件拣放，公布的成功率为 **96%**。同次发布还包括机器人安全基准 ASIMOV-Jailbreak，用来测试伪装成普通指令的危险请求。Ars Technica 与 The Decoder 对这次发布的报道也指向同一组动作。

这比单个实验室视频更接近工业现场，但“产线概念验证”仍与可复制的生产部署有距离。96%需要放进具体任务、工件、节拍和人工接管条件里读；如果每个工位都必须重新调参，漂亮的单点数据不会自然变成可规模化的机器人服务。官方没有给出跨工厂长期运行的可核实数据，因此不能把这次试验写成奔驰已大规模使用人形机器人。

对具身投资，最重要的新信号是同一发布把动作能力、真实场景和安全测试放在一起。机器人进入有人共处的工作环境后，任务成功率和拒绝危险操作必须同时达标。后续要看合作伙伴能否在未挑选的工件与班次里复现结果，也要看安全基准能否被外部团队用于比较不同控制模型。

## NVIDIA将OpenShell捐给CNCF，扩展Agent与GPU集群底座

[NVIDIA 官方博客](https://blogs.nvidia.com/blog/open-source-openshell-infrastructure/)称，公司把用于自治 Agent 安全与治理的 OpenShell 运行时贡献给 CNCF，并参与 Google 主导的 Agent Substrate。后者针对 Kubernetes 上的长时间运行 Agent 工作负载。同场公布的 DSX 组件包括 NVIDIA Kubernetes Engine、Recipes 与 Snapshot，目标是部署和管理 GPU 基础设施。这些是不同层次的组件，但共同指向 Agent 执行环境与 AI 集群运维。

值得区分的是，**进入 CNCF Sandbox 是社区治理的起点**，不是已经成为行业标准。NVIDIA 提供 GPU、网络和软件栈，现在又把 Agent 运行约束与集群工具放进开源生态，能降低客户开始试用的门槛，也有机会把运维习惯留在自己的平台周围。对于云厂和企业，开源许可证只是第一步；权限隔离、升级兼容与多厂商协作是否成熟，才决定生产系统是否会采用。

这条新闻与微软今天的权重后门研究相互呼应：一个强调执行时的边界，一个提醒进入执行环境之前就要审查模型来源。两者并非同一事件，却说明 Agent 基础设施的采购正在从“能否跑起来”转向“谁能解释、约束和追踪它做过什么”。

## Zen 6 EPYC迎来独立测试，核心密度与内存通道上升

[Tom’s Hardware](https://www.tomshardware.com/pc-components/cpus/amd-zen-6-epyc-venice-deep-dive-and-benchmarking-dual-epyc-9996-with-1-024-threads-delivers-up-to-93-percent-performance-gain-gen-on-gen-9686f-outclasses-nvidias-vera) 11月10日发布 AMD Zen 6 EPYC “Venice” 的首轮独立测试。文章描述标准 Zen 6 CCD 升至 **12核**、Zen 6c CCD 升至 **32核**，SP7 平台可提供16条内存通道；作者测试了两款处理器，并与 NVIDIA Vera 等平台比较。这是媒体当日发布的评测，不是 AMD 当天才首次推出 Zen 6 架构。把评测时间当产品首发时间，会抹掉这篇报道真正新增的独立信息。

核心密度和内存通道增加，理论上有利于多租户服务、数据处理和为 GPU 供数的 CPU 侧工作。但评测文章也显示，不同任务和进程放置策略会改变相对成绩；某个基准领先不能推断所有 AI 服务器负载都领先。更高密度还会把内存容量、带宽、散热和软件调度推到更显眼的位置，采购方需要看整机与机架层面的结果。

这也给今天台积电的资本支出决议一个技术侧注脚：先进制程需求最终要落到可交付的处理器、封装和系统配置。对服务器芯片投资，下一轮比较应优先使用相同软件环境和真实工作负载，连同功耗与总拥有成本一起测，而不是把单个峰值性能数字当成订单前景。
