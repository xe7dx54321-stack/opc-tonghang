今天的线索集中在一个问题：AI 从模型能力走向真实任务时，人才和算力只是起点，能否定位失败、控制运行成本并交付结果更难回答。本期保留三条有原文与时间证据的材料，不用旧发布补足条数。

## 李沐出任 Aimotion 联创兼 CTO，继续担任 Boson AI 职务

[机器之心报道](https://mp.weixin.qq.com/s?__biz=MzA3MzI4MjgzMw==&mid=2651074549&idx=1&sn=5af6f646bcad4a81a50fe188d15649b2)，李沐出任 Aimotion 联合创始人兼 CTO，负责产业级 AI 技术体系建设，同时**继续担任 Boson AI 联合创始人兼 CTO**。这不是简单地从一家离职、加入另一家；按报道的说法，双方希望把 Boson AI 的底层模型能力与 Aimotion 的产业场景结合起来。

这里的“世界模型”也需要具体理解。报道描述的方向不是物理仿真，而是对商业规则、客户决策和业务因果关系建模，让 Agent 有机会参与场景推演与更长周期的任务规划。Aimotion 原有业务聚焦汽车等行业的 AI 销售与营销解决方案；报道还称，公司会择机公布后续技术和产品进展。

从投资角度看，值得关注的不是把“世界模型”这个标签直接等同于新一代机器人基础设施，而是模型团队是否能与行业工作流真正结合。销售场景的价值不只在回答问题，还要看系统能否处理跨系统数据、在需要时交由人审核，以及在真实客户环境中稳定完成任务。以上是需要验证的方向，并非报道已证明的产品能力或财务结果。当前公开材料仍不足以判断具体客户、部署规模和商业回报。

## Tensward 剖析 H100 推理：GPU 占用率无法解释等待原因

[Tensward 的技术文章](https://tensward.com/blog/gpu-busy-doing-what)复盘了一次模型推理排查：H100 服务同时接收 16 个客户端请求时，`nvidia-smi` 显示 GPU 忙碌比例约 **35%**，而吞吐量和首 token 等待时间并不理想。作者指出，这个指标表示一个采样周期内至少有一个 kernel 在运行的时间占比；它本身既不能解释其余时间为何等待，也不能说明 kernel 运行时用满了多少芯片资源。

团队因此统计 kernel 和内存拷贝，发现该配置中每个请求会把大量状态从 GPU 复制回主机内存。作者随后比较了不同 `llama.cpp` 版本，看到同一负载的性能变化；这些都是其特定软硬件组合下的观察，不应直接当作其他服务的收益预测。文章由工具开发者发表，也需要把测试方法和其产品利益放在一起看。

这对推理基础设施的采购很实际：GPU“没跑满”并不自动意味着再堆卡或简单提高并发就能解决问题。先拆清楚主机与 GPU 之间的数据搬运、服务实现和请求调度，才能知道瓶颈究竟在算力、带宽还是软件路径。利用率是排查入口，不是单位 token 成本的完整解释。

## 独立实验让模型玩侦探游戏书：重试改善表现，但长期归因仍难

开发者 Waldek Mastykarz [公布了一项游戏书实验](https://blog.mastykarz.nl/llms-play-detective-gamebook/)：他通过 GitHub Copilot SDK，让模型玩一本 1988 年侦探游戏书及其续作，共进行了 **95 组运行、646 局游戏**。作者称，在他测试的模型和设置中，95 次首次尝试全部失败；允许模型查看此前过程并重试后，一些较强模型的表现有所改善。

这类任务的难点不是每一步都明显困难，而是一次看似合理的早期选择，可能在很多步之后才造成失败。作者观察到，模型可以从部分失败中吸取教训，但不总能把最终失败归因到此前缺失的线索。实验中模型没有文件或互联网工具，任务环境和反馈方式均由作者设计；少量不同重试预算下的结果也不能直接当作模型之间的严格排名。

对 Agent 团队而言，这个实验更像一面小镜子：单步准确率或一次演示成功，无法覆盖长任务中错误累积与恢复的代价。除了最终成功率，值得同时测量失败能否定位、重试预算、每次成功的成本，以及真实任务是否具备类似的反馈条件。一个文本游戏不能证明生产环境里的效果，但提出了可以在真实工作流中继续验证的问题。
