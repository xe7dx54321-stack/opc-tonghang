今天的变化集中在两个接口上：Google 和 AWS 把 Agent 需要的判断与检索拆成更直接的服务，Serve Robotics 则尝试把现实世界的配送能力开放给第三方调用。另两条模型新闻提醒我们，发布时给出的参数或漂亮样例，与用户在真实任务中获得的收益仍是两回事。

---

## Google推出Gemini Decisions API，专门给Agent做概率判断

[Google 官方公告](https://blog.google/innovation-and-ai/technology/developers-tools/gemini-decisions-api/)推出 Gemini Decisions API，底层是 Gemini Decision 1。它接收一份文本、图像、音频、视频或 PDF 输入，然后对最多 **1000个有限选项问题** 一次给出概率判断。Google 举的用途包括工具选择、策略检查、模型路由和上下文评分。这些问题通常不需要模型写出一段话，只需要足够可靠地回答“该走哪条分支”。

这项产品把 Agent 工作流里常被大模型顺手承担的小决策单独拿出来。一个复杂 Agent 可能反复问“是否调用搜索”“用哪一个工具”“检索片段是否相关”，每次都走生成式输出会积累延迟和费用。Google 报出的价格是 **每百万输入 Token 0.10美元、输出不计费**；共享输入按一次请求计费，各问题的指令和标准仍会计入输入量。这是 API 标价，实际任务成本还取决于问题设计、重试和整个工作流的调用次数。

Google 称模型在其测试中兼顾速度与校准度，但这些结果仍是厂商测试。采购方真正要比较的是：给定同一批真实决策，概率能否稳定映射到正确动作，误判代价高的分支能否设阈值交给更强模型或人工处理。如果答案成立，Agent 的竞争会从“一个模型包办所有步骤”转向按任务组合不同的判断器；如果校准失效，便宜的单次调用也会被后续错误吞掉。

## DeepMind发布AlphaGenome 2，按细胞类型预测遗传变异影响

[Google DeepMind 的发布](https://deepmind.google/blog/alphagenome-2-deciphering-how-cells-read-dna-to-better-understand-disease/)把 AlphaGenome 更新到第二代。它试图回答一个比“某段 DNA 有何作用”更细的问题：同一遗传变异在不同细胞类型里会怎样影响基因调控。DeepMind 称模型可以把特定细胞状态作为条件，帮助研究者定位与疾病相关的变异效应；这属于计算预测，距离确认病因或疗法仍需要实验。

这里有一个重要的产品边界。**非商业研究现可通过 AlphaGenome API 使用，商业研究仅为私人预览**。因此，对药企和生物技术公司而言，今天不是一个可无条件接入生产研发流程的商业发布。它更像是在提供新一代研究工具，让团队筛选哪些变异和细胞组合值得优先投入湿实验。

第一代基因组模型更容易给出组织层面的平均图景，细胞类型条件预测则可能把信号定位到真正相关的细胞。这个方向若能在独立数据上复现，可以减少盲目验证的范围；但某个变异在模型里分数更高，不等于患者中有相同效应。投资上该追的不是一张模型榜单，而是研究团队使用它后，实验命中率、验证周期和可解释性有没有改善。DeepMind 官方给出的性能数字可作为试验假设，不能代替外部实验室的复现。

## 英国AI芯片公司Fractile完成7.2亿美元C轮融资

据 [TechCrunch 报道](https://techcrunch.com/2026/11/11/with-720m-round-britains-fractile-gets-a-leg-up-in-the-race-for-ai-chips/)，英国 AI 芯片公司 Fractile 完成 **7.2亿美元 C 轮融资**，英国主权 AI 基金参与。公司瞄准模型推理，不只做芯片，也做让模型在自家硬件上执行的机器学习编译器。这是一轮融资，不能把政府参与和媒体披露的融资额当成两笔资金。

推理芯片公司的难题已经不只是提出另一种架构。客户要把现有模型和工具链迁过去，必须看到整体吞吐、延迟、能耗与维护成本的收益。编译器因此不是附属品：如果软件迁移很费力，硬件上即使有单项性能优势，也很难形成稳定采购。Fractile 获得的大额资金让它有资源同时推进硬件与软件，但报道没有提供足够的公开客户负载或大规模交付数据来证明这条路线已经跑通。

这轮融资也显示，资本仍愿意为“降低推理成本”下注，而且政府把本土硬件能力纳入投资叙事。对半导体投资，下一组应核对的事实是芯片何时交付、哪些模型能无损迁移、客户在真实负载上节省多少。把融资估值当作产品竞争力，或把主权基金参与理解成确定订单，都会过早下结论。

## AWS为Bedrock AgentCore推出可直接调用的网页搜索API

[AWS 官方技术博客](https://aws.amazon.com/blogs/machine-learning/introducing-the-web-search-api-on-amazon-bedrock-agentcore/)宣布 Bedrock AgentCore Web Search API。此前，开发者要通过 AgentCore Gateway 为网页搜索配置目标，再由 MCP 客户端调用；现在自己的代码可以用 AWS SDK 或 CLI 发起一次签名请求。结果返回排序后的网页条目及文本摘录，在可用时附标题、URL和发布时间；调用沿用现有 IAM 凭据，**无需先创建 Gateway 资源**。

变化看似只少了几个配置步骤，实际影响的是搜索在企业 Agent 架构里的位置。平台团队仍可用 Gateway 统一治理共享工具；单个应用只需检索时，可以直接把搜索嵌入已有代码和权限体系。这降低了做原型和接入实时信息的门槛，也使搜索更像普通云 API，而不是必须先部署的 Agent 平台组件。

但 API 返回的“发布时间”只是检索结果字段，并不会自动证明原始网页的时间或事实正确。Agent 如果拿它回答价格、政策或产品变化，仍需处理来源筛选、摘录缺失和网页更新。AWS 提供了便于集成的接口，商业价值要看搜索覆盖、可用性和调用成本在真实工作流里是否优于企业现有方案。今天能确认的是调用方式的改变，而不是检索质量已经胜出。

## Serve Robotics开放配送机器人API和开发者沙盒

[The Robot Report 报道](https://www.therobotreport.com/serve-robotics-opens-robot-delivery-network-for-others-to-build-on/)，Serve Robotics 推出 AV Delivery Developer Portal，允许第三方通过公开 API 请求其人行道配送机器人，并先在沙盒里测试应用。公司称已在美国和澳大利亚部署超过 **2000台机器人**；这个车队数字来自公司向媒体提供的信息，并非本轮新交付的数量。

这一动作的核心是把机器人服务从自营配送流程向外部软件开放。餐饮之外的开发者可以尝试把实体配送接进自己的业务系统，而无需先拥有车队。对 Serve 来说，开放接口的收益取决于已有覆盖区域能否被更多应用复用：同一台机器人如果服务更多稳定订单，资产利用率就可能提高；如果开发者只在沙盒里试用，开放 API 本身不会产生收入。

需要把“任何人可测试”与“任何地方都能叫车”分开。真实调用仍受车队所在城市、路线和运营能力限制，报道也没有给出外部开发者带来的订单量。机器人平台化的验证指标，应是第三方持续调用、每台车的有效任务时间、异常接管成本和合作方留存，而不是开发者门户上线后的注册数。与软件 API 相比，现实世界接口的供给边界更硬，这正是这条新闻值得跟踪的地方。

## 百度发布文心5.5 Flash Preview，强化编程与3D建模

据 [雷峰网 11月11日的报道](https://www.leiphone.com/category/industrynews/sqz0hf4DoTPX5mqI.html)，百度发布文心 5.5 Flash Preview。报道引述的发布方参数为总规模 **2800亿参数、每 Token 激活140亿参数**，最长上下文100万 Token；百度把编程、3D 建模和知识工作列为重点。Preview 是预览版本，不能直接等同于稳定商用版。

这次的产品定位不止是问答。报道称，模型针对代码库修复、复杂应用构建及 Blender、CAD 等工具使用进行训练。模型如果能在这些工作流里持续规划、调用工具并修正错误，会比单次生成漂亮代码更有价值。3D 场景尤其如此：用户要的是能继续编辑的模型或资产，图像看起来像设计图并不足够。

目前报道中的基准成绩和速度描述主要来自厂商，尚缺少在同一环境、同样任务上的独立复测。对企业采购，接下来要看预览版的实际接入条件、长任务成功率、人工返工时间与计费方式；参数量和上下文上限只能说明设计空间，不能直接推导出生产率。百度把编程和设计工具一起放进发布重点，也说明国内模型竞争正在从通用对话延伸到可操作的软件工作流。

## 智东西实测MiniMax H3-Image，关注开放权重后的复杂编辑能力

[智东西 11月11日的实测](https://mp.weixin.qq.com/s?__biz=MzA4MTQ4NjQzMw==&mid=2652813815&idx=1&sn=2b6a0855985ed9dbc638868c25ae320c)报道，MiniMax 在前夜发布 H3-Image 并开放权重。智东西编辑部用 MiniMax 海螺和 MiniMax Code 测试视觉表现、复杂任务理解与多参考图融合。正文给出具体样例，其中部分复杂任务由 Agent 负责拆解，再由图像模型生成结果；因此这些展示不能全部算作图像模型单独完成。

值得看的不是“又一张好看的图”，而是开放权重是否能让应用团队复用编辑能力。多参考图与复杂指令如果稳定，电商设计、游戏概念图和营销素材会有新的自动化空间。但单篇媒体实测展示的是挑选过的任务与输出，没有公开可重复的失败率、推理资源或与同条件模型的成本比较。智东西对效果的积极评价属于其主观测试，不能写成行业公认领先。

这条也与百度的发布形成一个有意思的对照：两家公司都在把模型能力推向创作工具链，区别在于图像权重开放给开发者自行部署或改造，会带来更大的实验空间，也把部署、版权与安全责任转给使用方。接下来需要看开发者在真实素材库和长批次任务里的结果，而不只是单张演示图。

## Google Labs推出Tabletop协作实验产品，先在美国开放候补

[Google Labs 公告](https://blog.google/innovation-and-ai/models-and-research/google-labs/tabletop/)推出 Tabletop。用户可把链接、文件和想法放进共享空间，再让工具生成行程表、投票、费用分摊或比赛对阵等可交互内容，群组成员可以同时使用。当前产品 **仅面向美国18岁以上用户通过候补名单开放**，不是全球公开上线。

Tabletop 的价值点是把一次生成的结果变成群组持续协作的对象。很多 AI 应用能写一份计划，却还要用户复制进表格或聊天群；Google 试图让生成内容本身成为可编辑的小工具。这个方向对轻量协作软件有启发，但今天只看到实验产品和开放条件，没有留存、付费或大型团队使用数据。它在日报里占较短篇幅，后续若真正开放并形成使用量，再评估商业竞争力。
