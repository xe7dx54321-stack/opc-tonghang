今天的线索可以连成一条成本链：模型厂商开始讨论完成任务要花多少 token，芯片用户希望缩短软件适配，集群运营商则把注意力投向网络和可靠性。机器人领域也有新融资和实际渠道上线，但融资额、装机能力与真实商业规模仍是不同的指标。

---

## 阿里推出 Qwen4-Max，主打长上下文与任务成本

The Decoder 报道阿里推出 Qwen4-Max。按照 Qwen 团队披露的参数，这是一款**总参数 2.4 万亿、每个 token 激活 710 亿参数**的混合专家模型，支持原生图像输入和百万 token 上下文。与只盯总参数不同，激活参数关系到单次推理实际动用的计算量；不过完整成本还受上下文长度、生成长度、缓存和系统部署影响，不能仅凭这两个数字排序。

报道介绍，新架构在处理长上下文时组合了压缩历史状态与选择相关信息的方式。阿里自己的 Work360 任务测试中，新模型相较上一代减少了 token 消耗，平均任务成本也下降；另一些评测中它在不同任务上的表现并不一致。这里的数字来自厂商测试和特定配置，既不是所有企业场景的报价，也不等于独立复现后的长期表现。阿里研究院的转载还介绍了 API 和多款应用中的使用入口，但原公众号网页本轮触发访问验证，正式证据采用可读的 The Decoder 报道。

值得关注的是竞争单位正在变化：以前模型排行榜经常比较一次回答是否更好，现在企业还要算**完成一项任务需要几轮调用、多少上下文和多少人工复核**。模型更便宜但反复出错，未必能降低流程总成本；反过来，一次调用略贵但重试更少，也可能更划算。Qwen4-Max 对国内应用团队的实际吸引力，仍要看各自任务上的成功率、延迟、数据合规和完整账单，而不是只看厂商选取的基准。

## Agile Robots 获 5 亿美元 F 轮融资，扩建机器人产能

The Robot Report 报道，Agile Robots 完成 **5 亿美元 F 轮融资**，估值 85 亿美元，累计融资达到 20 亿美元。软银领投，参投方包括英伟达、日立集团及 T.Capital。公司表示，新资金将用于扩大生产能力和国际市场，并强化美国业务。

Agile Robots 的产品并不只有人形机器人，也覆盖移动机器人、机械臂、灵巧手以及相关软件和模型。报道援引公司信息称，其德国 Fürstenfeldbruck 生产基地今年投入使用，具备每年生产多达一万台轮式和足式人形机器人的能力。这里是**产能**，不是已经生产或交付的数量；公司此前部署的工业机器人总数，也不能全部算成人形机器人出货量。

融资将竞争焦点推到更难的环节。实验室里的动作展示和可重复生产之间，隔着零部件供应、质量控制、安装集成、现场维护以及客户工作流程改造。对投资人来说，下一次值得追问的不只是新一轮估值，而是订单是否转为收入、工厂利用率如何、每个客户需要多少定制工作，以及机器人停机时由谁承担服务成本。公司覆盖多种机器人形态有助于寻找工业需求，也让不同产品的毛利与交付能力更需要分开看。

## Anthropic 称 Claude 三天完成 AMD GPU 模型适配

Tom's Hardware 报道，Anthropic 向 IPO 投资者介绍了一个软件适配案例：Claude Mythos Preview 为一个 Anthropic 模型在 AMD MI355X GPU 上运行提示词处理工作负载，约用三天完成适配；公司称类似的传统工程工作过去需要六至十二个月、数十名工程师。Anthropic 的说法是适配过程中模型迁移或编写了几乎全部相关 kernel，且基本不需要人工干预。

这个案例的边界很重要：三天指的是**一个模型、一个硬件平台和提示词处理阶段**达到公司认为有用的性能，并不是完整训练与推理系统在所有负载上完成优化。六至十二个月是 Anthropic 对过去项目的历史比较，而不是同一任务的严格对照实验；报道没有提供足以独立复现的完整代码、验收标准和人力成本。把它写成“AI 已经完全消除 GPU 适配成本”会超过现有证据。

即便如此，方向值得跟踪。长期以来，芯片迁移的难点不只是把代码翻译过去，还包括调优 kernel、验证数值正确性、适配集群以及持续处理软件更新。如果模型能把其中一部分重复工程显著压缩，采购方就更容易尝试第二种加速器；但不同硬件的内存、互联和实际运行效率仍然不同。CUDA 的成熟生态和生产经验不会因一次厂商案例立即消失。下一步更有说服力的证据，是第三方在新硬件、新模型和完整工作流上重复得到可核查的结果。

## Lambda 在万卡集群部署英伟达共封装光学交换机

英伟达表示，云服务商 Lambda 使用 NVIDIA Photonics 共封装光学（CPO）交换机连接 GB300 NVL72 机架，覆盖**超过一万颗 GPU**。按照英伟达文章介绍，Lambda 的测试中，网络延迟在机架级下降约 4%，在 pod 级最多下降约 10%；不同配置下的吞吐量与传统可插拔光模块方案相当。这些数字来自厂商披露的特定测试，不代表所有集群都能得到同样结果。

CPO 的思路，是把光学引擎与交换芯片更紧密地封装，而不是完全依赖传统可插拔光收发模块。集群扩大以后，GPU 间通信、电力和链路故障会影响大量任务；一次通信中断可能让昂贵的加速器等待。因此，即使单看某条链路的延迟降幅不惊人，持续训练任务能否减少中断、网络设备耗电能否降低，仍可能影响总体成本。

对产业链而言，这比一份抽象的 CPO 市场预测更具体：它显示方案正进入大规模部署场景。但厂商公布的对比没有替代采购尽调。客户仍需询问交换机与光学器件的维修方式、备件和停机时间、系统级功耗，以及相对现有网络的改造费用。只有把这些加在一起，才能判断节省的电费和训练时间是否足以覆盖新架构成本；也不能把英伟达的供应商陈述直接当成独立验证。

## 英伟达公布 Rubin HPC 加速器，计划 2028 年推出

Tom's Hardware 报道，英伟达在 SC26 公布 Rubin 家族新成员 Rubin HPC，面向科学计算、仿真以及与之结合的 Agent 工作流。公司称这款 GPU 将拥有**超过五万个 CUDA 核心**，并计划在 2028 年推出。报道同时指出，英伟达没有披露关键的 HBM 容量、带宽或完整芯片布局。

文章讨论了多芯片封装等可能性，但明确属于根据现有信息作出的推测，不是英伟达确认的产品结构。核心数量同样不能单独说明科学计算性能：不同任务对双精度、内存带宽和节点间通信的要求不同，芯片规格与整机设计都可能改变结果。距离计划推出还有较长时间，路线图也可能调整。

这则公告说明英伟达希望把科学模拟和 AI Agent 放进同一套基础设施叙事：模型提出假设或安排任务，仿真系统执行计算，再把结果反馈给模型。对于实际采购，重要问题是这条工作流能否缩短有效研究周期，而不是单纯让更多模型调用发生。现阶段没有完整规格、价格或独立测试，不能把远期产品当成今天可购买的算力，也不宜据此断言领先竞争对手。

## 英伟达公布 Vera Rubin 首批 MLPerf 成绩

英伟达称，Vera Rubin 平台首次出现在新一轮 MLPerf 结果中，覆盖训练、后训练和智能体推理。公司表示，其在 MLPerf Training v6.1 各项测试中取得领先，并称首次提交的 MLPerf Endpoints 结果显示，面向 Agent 的每瓦吞吐相较上一代提升超过十倍。**这些是英伟达对其提交结果的解读**，需要结合实际测试条目和对比配置阅读。

Agent 工作负载与单次问答不同：一次任务可能包含多轮生成、工具调用、等待外部系统以及更长上下文。因此，吞吐能效指标可以提供基础设施比较，但不能直接变成企业每个任务的成本。模型、精度、并发、时延约束和系统规模一旦不同，结果就未必可比；而且结果也不能直接证明所有真实应用都达到同样的代际提升。

与同日 Rubin HPC 的远期路线图不同，这条新闻讨论的是本轮已经公布的基准结果，而非 2028 年新品本身。对芯片采购方，更有用的下一步是拿目标模型和实际服务等级要求复测，查看每瓦有效任务数、端到端时延和集群总功耗。基准是筛选入口，不是绕过自身工作负载验证的理由。

## Zoox 无人出租车接入拉斯维加斯 Uber

TechCrunch 报道，亚马逊旗下 Zoox 的无人出租车已在拉斯维加斯接入 Uber，是 Zoox 首次与第三方网约车平台合作。现阶段乘客**不能直接指定 Zoox 车辆**；符合条件的 UberX、Comfort 等订单可能匹配到 Zoox。双方还与 MGM Resorts 合作改善酒店物业的上下车点、指示与乘客导航。

报道还称，Zoox 计划今年在洛杉矶启动初期运营，先面向员工及亲友，商业服务和通过 Uber 的乘车安排预计在 2027 年。未来计划与拉斯维加斯已经上线的服务不是同一个状态，不应写成洛杉矶现已全面商业运营。

对 Zoox 来说，Uber 提供的是既有需求入口：不必等待所有潜在乘客先下载独立应用。对 Uber 来说，更多自动驾驶合作伙伴可以增加可供匹配的运力。但渠道接入并不自动解决车辆供给、接驾等待、清洁维护和区域限制。双方也表示会从有限车队开始，后续扩大供应。要评估商业化，还需要看无人订单比例、车辆利用率、乘客等待时间和每英里的运营成本，而不是仅统计合作城市数量。

## Apple 测试 Siri AI 每日用量限制，付费套餐提高额度

The Verge 援引 MacRumors 报道，苹果在 iOS、iPadOS 与 macOS 27.3 测试版中，测试部分 Siri AI 和 Apple Intelligence 功能的每日设备用量限制。基础 Siri 指令仍免费且不设每日限制，受影响的主要是依赖云端处理的较复杂功能，包括部分多步骤个人情境请求、图像处理和依赖云端模型的自动化。

报道说，苹果尚未公布每种任务的具体每日次数，不同任务的额度可能不同；部分 iCloud+ 套餐将提供更高额度，50GB 套餐不在报道列出的扩额范围内。家庭共享成员使用共同额度池。这里是**测试版规则及媒体报道**，不是已经确认适用于所有用户的最终商业条款；地区、额度和正式版本都可能变化。

这件事的意义在于，操作系统级 Agent 一旦从简单指令转向多步骤推理，云端计算成本就需要某种分配方式。把额度与存储订阅结合，可以沿用已有付费关系，但用户也可能需要理解不同功能何时消耗共享额度。对应用开发者而言，设计体验时不能假设每一次云端调用都无限免费；对观察者而言，当前还不能根据测试条款推算苹果的推理成本或订阅收入增量。

## 英伟达推出四节点 DGX Spark HPC 开发套件

英伟达在 SC26 介绍 DGX Spark HPC Developer Kit：四台 DGX Spark 通过 ConnectX-7 环形直连，无须额外网络交换机，合计提供 **512GB 内存和 20TB NVMe 存储**。英伟达称，在 NVFP4 精度下可以跨四节点本地部署最高 7000 亿参数的模型；HPC SDK 的安装配置指南仍是即将推出，而非已经完整交付。

这套组合主要面向研究人员和开发者，让团队在桌面环境中调试多节点科学计算与模型工作流，不必每次都排队使用共享 GPU 集群。本地运行也可能方便处理尚未发表的研究成果和受限数据，但“可以本地部署”不等于任何模型都能以理想速度运行，也不等于四节点桌面系统具有大型集群的规模、容错或吞吐能力。

对小型科研团队而言，购买决策要比较整套硬件和维护费用、模型精度要求以及实际等待时间；对软件生态而言，更值得观察的是多节点调试能否平滑迁移到生产集群。公司给出的模型规模是特定量化条件下的能力描述，不应被理解为未经压缩的通用运行保证。
