## AWS Quick更新工作流与多智能体协作

AWS 宣布更新 Quick：用户可以在对话中描述业务流程，让系统构建连接 Agent、技能、工具和企业数据的工作流；新版加入**确定性步骤**，并支持更长的流程和更大的数据量。另一个变化是多 Agent 协作：不同专门 Agent 可并行处理请求，再由系统汇总结果。

这两类能力的组合，比单纯增加一个会聊天的入口更有意思。业务流程里既有适合模型处理的开放任务，也有必须按固定口径计算或校验的步骤。AWS 举的例子是财务团队生成月度报告：数据拉取、公式计算与阈值判断需要一致，解释性文字则可以由 Agent 起草。确定性步骤试图把两种性质不同的工作放在同一流程中，而不是让模型对每个环节自由发挥。

同时，AWS 更新了 Web 工作区，称任务在关闭标签页后仍可继续运行，并增加连接外部数据源和内容安全控制。这里仍是厂商公布的功能，不代表所有关键业务已经可以无人值守。企业采购更应该问：谁能授权访问数据，流程中间出错能否定位，输出和人工审批如何留痕。**能运行不等于可审计**，后者才决定流程能否从个人试用进入生产。

## Simplex AI公布Linger本地个人Agent

据量子位报道，前 DeepSeek 研究人员 Tony Zhang 创办的 Simplex AI 公布开源个人 Agent 项目 Linger，选择的入口是电脑而不是另做一个手机 App。报道介绍，它可以与本地环境及第三方模型配合，并在用户需要时允许人工接管。

项目的技术卖点是本地推理引擎 PolyStrata：按照报道，系统把不同频率使用的 MoE 专家模块分布在显存、内存和 SSD 上，再按需调度。团队给出的示例是在 RTX 3060 及配套内存上运行 125B 参数模型；报道中的生成速度是**团队数据，不是独立复现**，也不能只凭显存容量判断总硬件成本或所有任务体验。

这条路径的投资问题并不是“本地一定替代云端”。在电脑上执行任务，优势是贴近已有文件、浏览器和用户工作流；难点也在这里：授权边界、误操作恢复、不同机器的内存带宽，以及长时间后台运行的稳定性，都会直接影响留存。大模型能装进一台机器，只是个人 Agent 产品的起点；让它在真实环境里安全完成事情，是另一场验证。

## MachinePulse AI开源Karpo Decision 31B决策模型

量子位报道，MachinePulse AI 开源 Karpo Decision 31B，定位是为 Agent 的高频决策提供模型能力，例如在候选工具中做选择、判断任务是否完成，或者给结果打分。它不是要用一段长文本解释每次决定，而是通过专门的读取头输出候选项的概率。

这种设计瞄准的是 Agent 系统里容易被忽略的成本：浏览网页、检索或调工具时，系统可能需要反复做大量小判断。如果每一步都调用通用大模型生成回答、再解析文本，延迟与费用会随调用次数累积。报道称模型也采用分支注意力，让多道判断共享同一段上下文，减少重复计算。

团队展示了速度、准确率和概率校准数据，但这些主要是项目方口径；公开榜单或演示场景也不能直接推出生产环境的错误率。实际部署要比较的不只是单次推理快慢，还包括候选集构造、上下文处理、错误回退和人工介入的总成本。专门决策模型能否成为独立产品，取决于它在多种真实工作流中是否持续优于简单规则或通用模型。

## 腾讯混元团队在AMA讨论小模型路线与稀疏度取舍

甲子光年整理了腾讯混元团队的 Reddit 问答。团队表示，Hy4-mini 已进入路线图，也在考虑其他小尺寸模型；这属于**产品规划而非已经发布**。讨论中的另一个重点是 MoE 稀疏度：更少的激活参数不自动意味着更好的系统效率或模型质量。

按照报道转述的团队观点，在某些条件下提高稀疏度可以改善效率，但如果固定总参数量、单纯压低激活参数，模型质量可能下降，而大量权重仍占用内存。推理深度、长上下文追踪和工具调用可靠性，都是团队提到需要观察的能力。以上是团队的技术判断，不是经过独立实验确认的普遍定律。

对投资人而言，这比单看总参数或激活参数更接近产品问题：端侧设备受限的不只是算力，还有内存容量、带宽和应用延迟；模型既要装得下，也要在目标任务中保持足够可靠。混元是否能把路线图变成可下载、可复现且有竞争力的产品，仍要等后续发布。公众号原网页本次无法直接读取，使用带日期的 RSS 转存正文。
