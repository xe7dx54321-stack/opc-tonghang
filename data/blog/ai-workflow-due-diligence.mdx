## 一、为什么需要这个工作流

我每天会收到 5-10 份 BP。完整读完一份要 30-60 分钟。但在 90% 的情况下，**前 5 分钟我就能判断这个项目是否值得深聊**。

我想要的是：

1. 5 分钟内拿到 BP 的"结构化摘要"；
2. 同时拿到"红旗信号初筛"（不是结论，是问题清单）；
3. 把这两份结果直接存进我的 Notion 库，便于之后搜索。

Claude 完全能胜任这一步。下面是我用的 prompt（**已经过 20+ 项目验证**）。

## 二、Prompt 主模板

```markdown
# 角色

你是一位资深 PE/VC 投资人，专注硬科技方向（半导体、新能源、机器人、AI Infra），
有 10 年以上的尽调经验。你擅长用结构化思维快速判断一个项目的可信度。

# 任务

阅读以下这份 BP（可能包含融资计划书、商业计划、产品介绍等），
按下面的结构生成【BP 摘要】+【红旗初筛】。

# 输出格式

## 1. BP 摘要（结构化卡片）

### 项目元数据
- 项目名：
- 赛道（一级 / 二级）：
- 阶段：
- 融资金额：
- 估值：
- 核心创始人背景（一句话）：

### 一句话定位
（用 30 字以内说明项目在做什么、为谁解决什么问题）

### 商业模式
- 主要客户：
- 收入模式：
- 当前 ARR / 营收：
- 预计 12 个月 ARR：

### 关键差异化（团队自述）
（不超过 3 条，逐条保留原文措辞）

### 关键数据
（列出 BP 里所有用到的关键数字，包括但不限于：客户数、订单数、专利数、人员规模、毛利率、净利率、烧钱速度、跑道）

## 四、你的红旗初筛（10 个问题）

针对这个项目，**从投资人视角** 提出 10 个最值得在尽调中深挖的问题。
按"如果不解决会怎样"的严重性排序。

每个问题包含：
- 问题描述
- 假设（即你在担心什么）
- 推荐的验证方式（看哪个数据 / 找谁聊 / 跑哪个实验）

# 约束

1. 不要美化项目，也不要无脑挑刺——目标是"高密度地把信息暴露出来"。
2. 不要编造 BP 中没有的数据。
3. 输出严格按 Markdown 格式，便于直接复制到 Notion。
4. 如果 BP 中信息不足，明确指出"信息缺口"，不要臆测。

# 待分析 BP

{{BP_TEXT}}
```

## 三、配套工作流（Notion / Obsidian）

### 3.1 文件夹结构

```
/01-收件箱
  /2026-W37
    bp-acme-robotics.pdf
    bp-deepinfra.md  ← Claude 输出的结构化摘要
    bp-deepinfra-redflags.md  ← Claude 输出的红旗清单
/02-初筛通过
/03-深度尽调
```

### 3.2 自动化脚本（最小版本）

我用的是 **Raycast + Claude**：

```bash
# ~/bin/bp-digest.sh
# 用法：bp-digest.sh <pdf_or_text_file>
BP_FILE=$1
TEXT=$(pdftotext "$BP_FILE" -)
cat ~/.config/bp-prompt.md | sed "s|{{BP_TEXT}}|$TEXT|" | \
  llm -m claude-3-5-sonnet \
      --system "你是 PE/VC 投资人。" \
      > "${BP_FILE%.pdf}-digest.md"
```

`llm` 是 Simon Willison 的命令行工具，可以直接调用 Claude / GPT / 本地模型。
配合 Raycast 的 "Script Command"，一键把 BP 转成结构化摘要。

### 3.3 与 Notion 的对接

我用 **Notion API + Webhook** 把所有摘要自动归档到一个 "BP Library" 数据库。表结构：

| 字段 | 类型 |
|---|---|
| 项目名 | Title |
| 赛道 | Multi-Select |
| 阶段 | Select |
| 融资金额 | Number |
| 估值 | Number |
| 一句话定位 | Text |
| 红旗数 | Number |
| 初筛评分 | Number |
| 创建日期 | Date |
| 链接 | URL |

这个库一年下来会变成**我最值钱的资产**——比 CRM 更深，比 Notion 自带的表格更轻。

## 四、效果对比

| 指标 | 纯人工 | Claude 辅助 |
| --- | --- | --- |
| 单份 BP 处理时间 | 30-60 min | 5-10 min |
| 红旗识别覆盖率 | ~70% | ~85%（人工 review 后） |
| 摘要一致性 | 取决于当天状态 | 高（结构化） |
| 后续搜索 / 复用 | 几乎不可用 | 完全可检索 |

**注意：Claude 不是替你做判断，是帮你做"信息整理 + 风险暴露"。最终判断还是投资人做的。**

## 五、踩过的坑

1. **不要让 Claude 直接给"投资建议"。** 它的判断基于训练数据，对最新市场不敏感。
2. **不要把 BP 全文喂给第三方 API。** 用 Claude API + 企业版 / 本地 Ollama 更安全。
3. **一定要人工 review 红旗清单。** Claude 的红旗是"模板化的"——你的领域经验才让它"个性化"。
